# 长工课程表（ccsutSchedule）

一个只做一件事的安卓课表 App：**把你从教务处导出的 `xskb.xlsx` 直接变成手机上能用的课表**。
Kotlin + Jetpack Compose 从零实现，无第三方 UI 库、无网络请求、无账号、无广告。
界面是 Apple「液态玻璃」那一套：半透明磨砂面板浮在壁纸/渐变底色上。

## 功能

| 功能 | 说明 |
| --- | --- |
| 液态玻璃界面 | 半透明磨砂面板 + 顶部高光 + 柔和外阴影，**不描边**（没有那一圈白线）；背景可以是内置壁纸、自己的图片或纯渐变，面板会「透」出后面的颜色 |
| 玻璃模糊度可调 | 设置 → 外观 里有「玻璃模糊度」滑杆（很透 / 适中 / 磨砂 / 最厚），数字越大课程卡片越白越厚、课程色被冲得越淡；课程卡片、底部导航、卡片、弹层、对话框统一跟着变 |
| 周课表一屏 | 周一~周日 + 节次全部在一屏里显示，**不横向滚动**；节次多的时候纵向滚动 |
| 星期与日期 | 表头是「周一 / 9/14」两行，日期跟着所选周走；**今天那一列整块高亮** |
| 左右滑动切周 | 课表区域左右滑动换周，**跟手 + 松手吸附 + 顶部标题与日期一起滑**（`HorizontalPager`）；也可用两侧箭头或点周数弹出滚动选择器 |
| 长按拖动改期 | **长按课程卡片可以拖到别的星期 / 节次**：卡片会浮起来跟着手指，落点有虚框提示（放不下时变红），松手落位并闪一下；拖到上下边缘会自动滚动课表 |
| 同格最多 3 门 | 同一时段最多 3 门课重叠，第 4 门**存不下也拖不进去**：编辑页红字提示 + 保存置灰，拖动时落点变红并提示 |
| 当前节次高亮 | 当前时间落在某一节里时，节次号会变成实心蓝块 |
| 今日 / 下节课 | 点顶部的大号日期进入「今日」页：正在上 / 下一节课的名字、时间、教室与倒计时，下面列出今天全部课程 |
| 课程详情与增删改 | 点课程看详情（教师、教室、周次、冲突提示），可编辑、删除；点空格子直接加课 |
| xskb.xlsx 导入 | 解析教务处「上课啦」导出的课表，导入前有完整预览（学期、身份、课程清单、告警） |
| 作息时间设置 | 默认按本校时间（1-4 节 08:20 / 09:15 / 10:20 / 11:15 开始），可逐节修改、增删节次 |
| 上午 / 下午 / 晚上分界 | 第 4 节与第 8 节后各画一条跨整行的细分界线 |
| 第 1 周是哪一天 | 设置「课表第 1 周的周一」；选择器里直接列出第 1/2/3 周与最后一周的日期区间供你照校历核对 |
| 深色 / 浅色 / 跟随系统 | 一套由主色相推导的配色系统，5 种配色方案 |
| 课程配色 | 12 种课程色，同名课程同色，可在编辑页手动指定 |
| 背景 | 内置 3 张壁纸（默认「雪山草原」，另有「荧光海滩」「湖畔黄昏」）在设置里随点随换；也可以选自己的图片并调不透明度，自定义图片优先于内置壁纸；不选图片时用「自动配色」的渐变底色 |

底部是悬浮胶囊导航：**课程 / 设置**。选中块是一颗「水滴」——切换时从旧位置滑到新位置（弹簧），
滑动过程中横向拉长、纵向压扁，到位再回弹。

## 液态玻璃是怎么做的（以及为什么不掉帧）

参考视频里的玻璃感来自四件事：**磨砂填充 + 顶部高光 + 柔和外阴影 + 圆角**，
本项目就按这四样实现（见 `ui/theme/Glass.kt` 的 `Modifier.liquidGlass`），刻意**不做真实背景模糊**：

- Compose 里做背景模糊只能靠 `RenderEffect`（Android 12+），每个玻璃面板一层离屏纹理，
  一屏几十个课程格子必然掉帧；参考视频里的课程格子其实也没有真模糊。
- 「模糊度」是通过**磨砂填充的白度**做的：`glassFrost` 越大，填充越白越厚、课程色叠得越淡、
  顶部高光越明显——视觉上就是更模糊。所以拖滑杆能立刻看到效果，还不用付真实模糊的代价。
- 面板**默认不描边**：参考视频里的课程卡片没有那一圈白线，去掉之后才像一块磨砂玻璃。
- 背景是「底色光斑 → 壁纸（内置或自定义）→ 上下蒙层」三层，玻璃面板会真的透出后面的颜色。
  蒙层用**主题底色**而不是黑色：浅色主题配深色照片、深色主题配浅色照片，标题都读得清；
  顶部（大号日期那一行）压得重一点，中间几乎不动，壁纸还是壁纸。
- 上面这些在 Compose 里都是一次绘制调用（`background` / `drawWithContent`），几乎不花钱。
- 外阴影只给「浮起来」的东西用（悬浮导航、弹层、拖动中的卡片）；网格里的课程格子**不投影**。

手势与动画上的开销控制：

- 拖动状态放在 `State` 里，**只有浮层读它**；每帧重组的只有一个卡片，课表网格一帧都不重画。
- 网格里「当前是否在拖动」「拖的是哪门课」用 `derivedStateOf` 收敛成布尔值/id，避免每帧触发整页重组。
- 周次切换用 `HorizontalPager`（`beyondViewportPageCount = 1` 预组合相邻页，滑动第一帧不卡）。
- 自动边缘滚动只在「靠边程度」变化时重启协程，不是每帧重启。
- 背景光斑是**静态绘制**，没有任何常驻动画。

## 「开学」和「第 1 周」不是一回事

`xskb.xlsx` 里**只有「第几周有课」，没有任何日期**（文件创建时间、页眉都推不出开学日），
所以「第 1 周 = 哪一天」必须由用户指定：**设置 → 课表第 1 周的周一**。

你们学校的情况就是典型例子：9/19 开学、9/20 起军训，而**正式上课的第 1 周从 10/5 开始**。
如果把 9/19（周六）填进去，App 会把它归到那一周的周一 9/14，整学期日期全部偏掉。

为此做了四件事：

1. 设置项改成「课表第 1 周的周一」，并写明它不等于开学日；
2. 选择器里非周一会被**自动对齐到该周周一**，并显示对齐结果；
3. 选择器里给出「第 1 / 2 / 3 周 + 最后一周」的日期区间，以及今天落在第几周（照校历核对）；
4. 课表页顶部与「今日」页都会提示「今天还没到第 1 周 / 今天不在教学周内」，不会把某周的课误当成今天的课。

## 构建

环境：JDK 17+、Android SDK（platform 37 / build-tools 36+）。

```powershell
$env:JAVA_HOME='C:\Users\<你>\.jdks\java-21'
$env:ANDROID_HOME='D:\Android\Sdk'
.\gradlew.bat :app:assembleDebug      # 调试包：com.jingoujiao.ccsutschedule.debug
.\gradlew.bat :app:testDebugUnitTest  # 单元测试
```

正式包需要签名（没配置签名也能构建，只是产物未签名）：

```powershell
.\gradlew.bat :app:assembleRelease `
  -Pccsut.releaseStoreFile=D:/path/ccsut-release.keystore `
  -Pccsut.releaseStorePassword=****** `
  -Pccsut.releaseKeyAlias=ccsut `
  -Pccsut.releaseKeyPassword=******
```

也可以用环境变量 `CCSUT_RELEASE_STORE_FILE / _STORE_PASSWORD / _KEY_ALIAS / _KEY_PASSWORD`。
keystore 与密码**不要提交**（`tmp/` 已在 .gitignore 里）。

## 更新源与国内加速

GitHub 在国内直连常常只有几十 KB/s，所以更新做了双源 + 测速：

- **检查更新**：Gitee 与 GitHub **并行**查。Gitee 上已经有可下载的新版本就直接用它，不再等 GitHub
  （GitHub 的 API 在国内经常要等到超时）。
- **下载**：候选顺序是 `Gitee 直连 → GitHub 直连 → 公共加速镜像 → 自定义前缀`，
  先各读一小段测速挑最快的；下载过程中如果 10 秒内平均速度低于 40KB/s，**自动换下一个源**。
- **设置 → 常规 → 更新包下载源** 可切换：自动（Gitee 优先 + 测速）/ Gitee 优先 / 只用 GitHub /
  GitHub 镜像加速 / 自定义加速。Gitee 仓库默认 `jingoujiao/ccsut-schedule`，可在同一对话框里改。
- 更新弹窗里还有「复制链接」，方便用浏览器或下载工具自己下。

发版时建议 **Gitee 与 GitHub 发同一个版本号**（Gitee 供国内加速，GitHub 作为主仓库）；
只有一边有 Release 也能正常更新，只是慢一点。

## 发布新版本（应用内更新依赖这几条）

应用内「设置 → 常规 → 检查更新」走的是 GitHub / Gitee 的 `releases/latest` 接口，所以：

1. 仓库必须是**公开**的（私有仓库和没有 Release 都会返回 404，App 会提示「仓库还没有发布正式版本」）；
2. 新建 Release 时 **tag 用 `vX.Y.Z`**（例如 `v1.2.0`），版本号要比用户当前装的大；
3. **上传的资产文件名必须以 `.apk` 结尾**（例如 `ccsutSchedule-1.2.0.apk`），App 会自动挑 `.apk` 资产下载；
   Gitee 那边把同一个 APK 作为「附件」挂到 Release 上即可；
4. 每次发版同时把 `versionCode` 加 1、`versionName` 改成对应版本（见 `app/build.gradle.kts`）。

App 侧行为：「检查更新」手动检查；「自动检查更新」在启动时静默检查一次，发现新版本会弹窗，
点「下载并安装」→ 下载 APK 到 cache → 交给系统安装器（首次需要在系统里允许本应用安装未知来源应用）。

权限只有两个：`INTERNET`（仅访问 GitHub Releases）与 `REQUEST_INSTALL_PACKAGES`（安装下载的更新包）。

## xskb.xlsx 解析约定

文件是「节次列 + 星期X 列」的网格，单元格里可能塞了多门课：

```
高等数学2（上）

于卫东【5-18周】
7-南203
```

解析规则（见 `data/XskbParser.kt`，全部可单测）：

1. 表头优先按文字识别“星期X”，识别不出来时退化为按列序（第 2-8 列 = 周一至周日）并给出告警；
2. 节次列支持两种写法：**一行一节**（`1`、`2`、`10`）与**一行两节**（`1-2`、`第5-6节`、`1、2`、`5至6`）；
   同时展开 xlsx 的**合并单元格**（两节连上的两行被合并成一格时，值会自动填满整块）——
   这两种情况若不处理，就会出现「占两节的课只占一节」；
3. 以「含【周次】的行」为锚点：它上面最近的非空行是课名，下面紧邻的行是教室；
4. 只有**节次相邻**且课名/教师/教室/周次完全相同的块才合并（第 1-2 节与第 5-6 节不会并成一张卡）；
5. 周次支持 `5-12周`、`16周`、`1-4,6-8周`、`6—17周`（全角破折号）、`5、7、9周`、`第5-12周`、单双周；
6. 文件底部只有节次号、没有课的行（如 `9.0`）不计入作息节次。

文件里**没有**开学日期和作息时间，所以这两项必须在设置里自己填——这是文件本身的限制，不是解析问题。
其中日期要填的是「**正式上课第 1 周的周一**」，见上一节。
